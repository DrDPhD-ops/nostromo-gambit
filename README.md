# NOSTROMO GAMBIT

Шахматы с орбитальным десантом. Двое играют обычные шахматы, а внутри крутится
настоящий Stockfish — но не как соперник, а как **арбитр баланса**.

Периодически на доску высаживается подкрепление: обеим сторонам одновременно
выдаётся *разный по составу* материал (белым пешка со слоном, чёрным ладья) на
*конкретные поля*, подобранные так, чтобы оценка позиции в сантипешках не
сдвинулась. Партия перестаёт упираться в размен: материал приходит снова, а
перевес, заработанный игрой, сохраняется.

Оформлено восьмибитным терминалом корабля: зелёный фосфор — колониальные
морпехи, янтарный — ксеноморфы. Обе расцветки настоящие: так светили мониторы
той эпохи.

## Быстрый старт

```bash
cd "G:/Другие компьютеры/PAULEKMAN/dev/nostromo-gambit" && npm install
```

```bash
cd "G:/Другие компьютеры/PAULEKMAN/dev/nostromo-gambit" && npm run setup
```

`setup` скачивает официальный релиз Stockfish (около 81 МБ), сверяет sha256 из
GitHub API, распаковывает в `%LOCALAPPDATA%\nostromo-gambit\engine\` и замеряет
скорость. Команда идемпотентна: повторный запуск только проверяет движок.

```bash
cd "G:/Другие компьютеры/PAULEKMAN/dev/nostromo-gambit" && npm start
```

Открыть `http://127.0.0.1:7777`.

> **Важно про рабочую копию.** Каталог на диске `G:` — это виртуальный том Google
> Drive. `npm install` там создаёт файлы **нулевой длины** (проверено: npm ловит
> `TAR_ENTRY_ERROR` и молча продолжает), а junction'ы не создаются вовсе. Поэтому
> живая копия проекта лежит в `C:\dev\nostromo-gambit`, а сюда исходники
> зеркалируются командой `npm run mirror`. Запускать игру лучше из `C:\dev`.

## Как играть

Стартовый экран спрашивает всё сразу, как в играх той эпохи:

| Параметр | Что делает |
|---|---|
| **Игрок 1 / Игрок 2** | человек или компьютер, в любых сочетаниях (можно и компьютер против компьютера) |
| **Уровень компьютера** | 1 «Рядовой» … 5 «MU-TH-UR 6000» |
| **Планировщик десанта** | МАТЬ / БИШОП / ЭШ — характер подкреплений, см. ниже |
| **Расстановка** | стандартная или Фишера (960) |
| **Бросков кубиков** | сколько раз за партию каждый может вызвать десант вручную |
| **Авто-десант** | раз в N ходов, либо по профилю планировщика, либо выключить |

Ход делается перетаскиванием или двумя кликами: по фигуре, затем по полю.

### Два способа вызвать десант

**Автоматически** — раз в N полных ходов. Ровный десант, цель по балансу — ноль.

**Кубиками** — у каждого игрока несколько бросков за партию. Бросок 2d6 решает
две вещи сразу:

```
сумма   → тоннаж:  60 + 90 × (сумма − 2)     = 60 … 960 сп материала
разброс → перекос: 20 × |d1 − d2|            = 0 … 100 сп в вашу пользу
```

Напряжение встроено в сами кубики: дубль даёт максимум тоннажа и **ноль**
перекоса, а максимальный перекос (6–1) — всего семь очков тоннажа. Выкрутить
и объём, и наглость одновременно нельзя.

Подкрепление получат **обе** стороны — смысл нажатия в том, что ход остаётся за вами.

### Планировщики

Разница между ними не сводится к допуску по сантипешкам. Позиция может стоить
ровно ноль и быть при этом практически неиграбельной для человека: единственный
ход, скрытая связка, фигура, которую нечем защитить. Счётчик сантипешек этого не
ловит — ловят отдельные измеримые величины (разброс оценки по глубине, отрыв
лучшего хода от второго, перекос давления на королей и подвижности).

| | **МАТЬ** | **БИШОП** | **ЭШ** |
|---|---|---|---|
| Допуск | ±15 сп | ±30 сп | ±30 сп |
| Свой люфт | нет | нет | до ±80 сп, знак случаен |
| Что выбирает | самые тихие расстановки, любит зеркальные | ровно то, что говорит арифметика | самые острые и ловушечные из тех, что формально ноль |
| Авто-десант | раз в 6 ходов | раз в 4 | раз в 3 |

## Главное ограничение, которое стоит понимать

**На доске никогда не бывает больше 32 фигур.** Это не наше решение: партия
начинается ровно с 32, и в шахматах материал может только убывать. Проверено и
на движке — 32 фигуры он считает, на 33-й завершается с кодом 1.

Отсюда следствие для всей механики: **десант не наращивает материал, он
восполняет потери.** Пока никого не разменяли, высаживать некуда, и игра честно
пишет «ТРЮМ ПОЛОН — ДЕСАНТ ПОСЛЕ ПЕРВЫХ ПОТЕРЬ». Зато партия перестаёт
скатываться в голый эндшпиль: каждое взятие открывает слот под подкрепление.

### Как ищется сбалансированный десант

Наивный перебор нежизнеспособен: три фигуры по тридцать пустых полей — это
около пятнадцати тысяч совместных расстановок, и даже по 60 мс на оценку
получается четверть часа на один десант.

Работает наблюдение: задача о балансе почти одномерна. Вклад отдельной фигуры на
отдельном поле измеряется **один раз** статической оценкой (~2 мс), а дальше
ищется не расстановка, а **пара сумм**, дающая нужную дельту — двоичным поиском
по отсортированным суммам вместо перебора произведения.

```
0. маржинальная таблица   вклад каждой (фигура, поле) — статической оценкой
1. композиция встречным ходом  пары сумм, дающие нужную дельту
2. отбор движком          короткий поиск по кандидатам (кратно размеру пула)
3. коррекция              промах предсказания измеряется по результатам отбора,
                          и цель сдвигается — вместо полного нового захода
4. подтверждение          длинный поиск по лучшим, с MultiPV 2
```

Если не сошлось: ремонт состава набора → другой набор → зеркальный десант →
расширение допуска (не более чем вдвое, и об этом честно пишется в журнале) →
отложить до следующего хода.

### Два правила, без которых всё остальное бессмысленно

1. **Бюджет задаётся в узлах, а не в глубине.** `go depth N` невоспроизводим:
   под чужой нагрузкой движок успевает разное количество работы и на той же
   «глубине» выдаёт другую оценку.
2. **Базовая оценка переизмеряется в каждом раунде тем же бюджетом, что и
   кандидаты.** Сравнивать глубокую базу с мелким кандидатом — систематическая
   ошибка больше всего допуска.

И отдельно: **счётчик 50 ходов обнуляется в обеих сравниваемых позициях.**
Stockfish демпфирует оценку к нулю по мере приближения к правилу 50 ходов, и без
этого сравнение «до» с `hmvc = 80` и «после» с `hmvc = 0` вносило бы ошибку
больше допуска.

## Проверка

```bash
cd "G:/Другие компьютеры/PAULEKMAN/dev/nostromo-gambit" && npm test
```

```bash
cd "G:/Другие компьютеры/PAULEKMAN/dev/nostromo-gambit" && npm run selfplay -- --games=5 --workers=2
```

```bash
cd "G:/Другие компьютеры/PAULEKMAN/dev/nostromo-gambit" && npm run bench -- --positions=12 --storyteller=all
```

Ночной прогон — главный оракул проекта. Юнит-тесты проверяют, что модули делают
написанное; прогон проверяет, что механика работает на длинной дистанции.
Самая важная его цифра — **знаковое среднее Δ**: она одна ловит ошибку
нормализации POV и систематический темповый перекос, которые по модулю взаимно
гасятся и в абсолютных метриках не видны.

## Известные ограничения

- **Рокировка в режиме Фишера отключена.** `chess.js` 1.4.0 принимает позицию
  960, но ходов `O-O` в ней не генерирует (проверено). Дописывать генерацию
  960-рокировки поверх библиотеки — вмешательство в её внутреннюю генерацию
  ходов; молча отдавать «Фишера со сломанной рокировкой» нечестно, поэтому права
  рокировки в этом режиме просто снимаются, и об этом сказано на стартовом экране.
- **Игра только за одним экраном.** Состояние живёт на сервере, так что сетевой
  режим добавляется без переписывания, но сейчас его нет.
- **Скорость поиска зависит от машины.** На этом ноутбуке (i5-10300H, базовая
  частота 2.5 ГГц) один воркер даёт около 0.6 Mnps, пять совокупно — около 1.8.
  Бюджеты пересчитываются от измеренной скорости при каждом старте.
- **Отмена хода после десанта перерисовывает доску целиком.** Восстановить, какой
  именно конь стоял на поле три хода назад, из FEN невозможно, поэтому
  идентификаторы фигур назначаются заново. Это честнее, чем притворяться.

## Лицензии и оговорки

- **Stockfish** распространяется под GPL-3.0 и вызывается **отдельным процессом
  по протоколу UCI** — конвенциональная слабая связь. Бинарь скачивается с
  официального релиза `official-stockfish/Stockfish` и не входит в этот
  репозиторий.
- **chess.js** — BSD-2-Clause.
- **Графика нарисована здесь же, программно**: спрайты фигур заданы битмапами
  16×16 прямо в `public/sprites.js` и разворачиваются в SVG. Внешних ассетов нет,
  сторонних лицензий на графику нет.
- Визуальный стиль — **оммаж** научной фантастике конца семидесятых. Чужие
  логотипы, товарные знаки и изображения не воспроизводятся; все названия и
  тексты написаны для этой игры.

## Переписка с Claude Code

В `.claude-sessions/` лежат сессии Claude Code, в которых делался этот проект (три сессии).
Сессии запускались из общей папки `G:\Другие компьютеры\PAULEKMAN\dev`, поэтому
в них может встречаться работа и над соседними проектами.
Значения `APP_PASSWORD` в переписке заменены на `[REDACTED]`.

Чтобы продолжить сессию на другой машине через `claude --resume`:

1. Скопируйте содержимое `.claude-sessions/` в
   `~/.claude/projects/G--------------------PAULEKMAN-dev/`
   (на Windows это `C:\Users\<имя>\.claude\projects\...`).
2. Запустите `claude --resume` из папки с тем же путём:
   `G:\Другие компьютеры\PAULEKMAN\dev`. Claude ищет сессии по пути рабочей
   папки, так что из другого пути он их не увидит.
